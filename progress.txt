### 会话管理重构 ✅ 完成 (NEW)

#### 问题分析
- 状态分散：`ChatController._session_cache`, `SidebarPanel._current_session_id` 多处存储
- 会话数据模型缺失：只有消息列表，无名称、时间戳、token 使用量
- UI 与数据逻辑混合：`SidebarPanel.switch_to_session()` 在做数据操作
- 消息缓存 Bug：助手消息未正确缓存（`full_response` 在赋值前检查）
- 线程安全隐患：子线程和主线程同时访问 `_session_cache`

#### 重构方案
- 新增 `SessionManager` 类作为单一数据源
- 新增 `ClientSession` 数据类（id, name, messages, timestamps, token_usage）
- `SidebarPanel` 简化为纯 UI 组件（移除 `_current_session_id`）
- `MainWindow` 添加 `_refresh_session_list()` 统一更新 UI
- 修复消息缓存：在 `send_message` 正确位置缓存用户和助手消息

### qasync 兼容性修复 ✅ 完成 (NEW)

#### 问题
重构后测试时，程序在创建 OpenAI client 时静默崩溃。原因是 `AsyncWorker(QThread)` 在子线程中创建新的 event loop，与 qasync 的 `QEventLoop` 不兼容。

#### 解决
使用 qasync 提供的 `@asyncSlot()` 装饰器替代 `QThread`：
- 删除 `AsyncWorker` 类
- `_on_message_sent()` 改为使用 `@asyncSlot()` 装饰器
- 所有异步操作在主线程的 `QEventLoop` 中运行

#### 教训
- qasync 要求所有异步操作在主线程的 `QEventLoop` 中运行
- 不能在 QThread 中创建新的 event loop
- 遇到框架兼容性问题，先查阅框架文档

### HTTP Transport 多协议支持 ✅ 完成

#### 实现
- **Streamable HTTP (2025-11-25 新标准)**：单一端点 `/mcp`，POST 发送消息，GET 可开 SSE 流接收服务器推送
- **HTTP+SSE (2024-11-05 已弃用)**：分开的 POST `/message` 和 GET `/sse` 端点
- **FastMCP SSE (变种)**：动态端点发现，GET `/sse` 返回 `event: endpoint` + `/messages/?session_id=xxx`

#### 协议自动检测
1. POST `initialize` 到 `/mcp`
2. 如果 200 OK → Streamable HTTP
3. 如果 400/404/405 → GET `/sse` 进一步检测
4. 解析 SSE 首个事件区分 FastMCP 或 HTTP+SSE

#### Session 自动重连
FastMCP SSE session 过期后（POST 返回 404）自动重连 `/sse` 获取新 session_id 并重试请求。

#### SSE 流超时修复
设置 `sock_read=None` 防止 aiohttp 默认超时导致 SSE 流断开。

- `packages/sdk/src/harness/mcp/transport.py`: 多协议支持、自动检测、session 重连、超时修复
- `packages/sdk/docs/09-mcp-integration.md`: 更新 HTTP Transport 文档

#### SSE 长连接超时修复 ✅

**问题**: 客户端使用 SSE MCP 服务器时出现超时断开，而 Claude Code 内部没有此问题。

**根因**: 虽然之前设置了 `sock_read=None` 解决 SSE 读取超时，但 `total=30` 秒的总超时仍会限制整个 SSE 连接时长。SSE 是长连接协议，服务器可能长时间不推送事件，导致连接被错误断开。

**解决方案**: 使用**双 Session 策略**：
- `_sse_session`: `total=None, sock_read=None` - 无限超时，用于 GET `/sse` 长连接
- `_session`: `total=timeout` - 可配置超时，用于 POST 请求

**文件更新**:
- `packages/sdk/src/harness/mcp/transport.py`: 添加 `_sse_session`，分离 SSE 长连接和普通请求的超时配置
- `packages/sdk/docs/09-mcp-integration.md`: 添加 SSE 长连接超时处理文档

#### FastMCP Session 重连修复 ✅

**问题**: MCP 工具调用返回 404，显示 "FastMCP session expired"，重连后仍然失败。

**根因分析**:
1. `_reconnect_fkmcp` 方法在重连时没有检查 `_sse_session` 是否存在/有效
2. 如果 `_sse_session` 被关闭，`_sse_loop()` 会直接 return，永远不会发现新的 endpoint

**修复**:
1. `_reconnect_fkmcp` 中添加 SSE session 检查和重建逻辑
2. `_sse_loop` 中添加详细的日志记录，便于诊断 SSE 连接状态
3. 正确处理 SSE ping 注释行（以 `:` 开头）

### Chat Panel 消息气泡高度修复 ✅ 完成

#### 问题背景
对话框在 AI 回复后出现大块空白区域，消息气泡高度异常。

#### 问题分析
1. `QScrollArea.setWidgetResizable(True)` 会强制 widget 填满视口高度
2. `setAlignment(Qt.AlignmentFlag.AlignTop)` 在 `setWidgetResizable(True)` 时无效
3. `sizePolicy` 设置被 `setWidgetResizable` 行为覆盖

#### 解决方案
使用 `minimumHeight` + `maximumHeight` 硬约束控制容器高度：
- `MessagesContainer._update_height()`: 手动计算内容高度
- 每次添加消息后更新容器高度
- 同时设置 min/max 高度防止被扩展

```python
def _update_height(self):
    """更新容器高度以适应内容。"""
    total_height = 32  # 上下 margin (16 + 16)
    for i in range(self._layout.count()):
        item = self._layout.itemAt(i)
        if item and item.widget():
            total_height += item.widget().sizeHint().height()
    self.setMinimumHeight(total_height)
    self.setMaximumHeight(total_height)
```

同时修复子组件的 sizePolicy：
- `MessageBubble`: 垂直方向 `Minimum`
- `MessageRow`: 垂直方向 `Minimum`

## 2026-06-28

### Loop Engineering Phase 1: Goal Verifier ✅ 完成

#### 背景
Loop Engineering 是 2026 年 6 月兴起的新范式：**不再逐轮手动提示 Agent，而是设计自动化循环系统驱动 Agent**。

核心公式：`Loop = Trigger + Context + Action + Verification + State + Stop rules`

#### 实现内容

**类型定义** (`loop/types.py`):
- `GoalConfig` - 目标配置（description, success_criteria, workspace_dir, max_iterations, timeout 等）
- `GoalResult` - 执行结果（status, total_iterations, verification_log 等）
- `GoalStatus` - 状态枚举（ACHIEVED, TIMEOUT, MAX_ITERATIONS, MAX_RESETS, ERROR, VERIFIER_FAULT, CANCELLED）
- `VerificationResult` - 验证结果（achieved, confidence, reasoning）
- `VerificationRecord` - 验证记录（iteration, achieved, confidence, reasoning）

**GoalVerifier** (`loop/goal.py`):
- LLM 验证：让 LLM 判断目标是否达成
- 自定义验证：用户提供的验证函数（支持同步/异步）
- 指数退避重试：处理 LLM API 限流
- 无状态设计：所有上下文通过参数传递，支持并发执行

**GoalLoop** (`loop/goal_loop.py`):
- 迭代控制：max_iterations, max_context_resets
- 上下文重置：防止 "context anxiety"（token 接近模型限制时自动重置）
- 超时处理：timeout_seconds
- 成本控制：max_tokens, max_cost_usd
- 进度回调：on_progress 参数

**AgentHarness 集成** (`sdk/harness.py`):
- 新增 `run_goal()` 方法
- 简化 API：`result = await agent.run_goal("修复所有类型错误")`

#### 设计原则

1. **GoalVerifier 无状态性**：
   - 所有上下文通过 `context` 参数传递
   - 支持并发执行多个 Goal（Phase 3 Worktrees 预留）
   - 便于测试（无副作用）

2. **异步设计**：
   - 每次迭代后 `await asyncio.sleep(0)` 让出控制权
   - 防止阻塞事件循环
   - 支持长时间运行（数分钟/数小时）

3. **验证器容错**：
   - `VERIFIER_FAULT` 状态区分基础设施故障
   - 指数退避重试（API 限流、网络超时）
   - JSON 解析失败直接返回故障状态

# 基础用法
