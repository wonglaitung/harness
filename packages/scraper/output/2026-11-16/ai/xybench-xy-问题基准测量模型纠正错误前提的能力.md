# XYBench — XY 问题基准：测量模型「纠正错误前提」的能力

## 技术定义 (What)
XYBench 是 AllenAI 联合 CMU / NVIDIA / Johns Hopkins 发布的 8,115 条「含误解提问」基准。每条查询都标注了 stated request（Y，用户字面要求的方法）与 intended request（X，用户真正想达成的目标），并用三条 rubric 评分：是否给出 S-solution（Y 的解法）、是否识别出 X 与 Y 之间的误解、是否给出 I-solution（面向 X 的替代方案），同时测量回答的「重心」落在 Y 还是 X。获 EMNLP 2026 Best Resource Paper。

## 行业痛点 (Why)
真正有用的助手必须能应对「问错问题」的用户，而不只是「问对问题」的用户。但现有 benchmark 几乎只测「给定正确问题的回答质量」，完全没有度量模型能否识别用户的隐含错误前提并主动纠偏——而这正是用户实际求助时最常见的情形（如「怎么让糖霜不滑落」的真实问题是蛋糕胚太热）。

## 旧范式 vs 新范式
- **旧做法**：旧做法：评测只考「答案对不对」。模型对「如何用正则解析 XML」给出一个完美的正则，就算满分——即使它强化了用户选错方法这一根本错误。
- **新做法**：新做法：把「语用学（pragmatics）」变成可量化指标。评测拆成三个独立维度（方案存在性 / 误解识别 / 回答重心），从而区分「顺带提了一句真实解法」与「真正把回答重心转移到真实目标上」。并用 oracle 实验（显式告知 X）隔离出「识别意图」与「依意图行动」两个失败环节。

## 生产力影响 (How)
实测结论极具行动价值：五大前沿模型（Claude Sonnet 4.6、GPT-5、Gemini 3.1 Pro、Qwen3.5-9B、DeepSeek-V4 Pro）在 Stack Overflow 上「主要聚焦真实目标」的回答仅 35-41%，而人类参考答案更高；更关键的是多项选择题中模型有 71-84% 能挑出「面向目标」的答案——即「能认出来但写不出来」，认知与生成之间存在系统性断裂。这直接指出后训练/提示工程的优化靶点，而非笼统地「加强推理」。

## 采用成本
低。数据集托管在 HF Hub（allenai/XYBench-dataset）自动下载，代码在 GitHub，通过 litellm 调用任意厂商模型，三条命令完成生成→评判→汇总。需自备各家 API key；LLM judge 默认用 Claude Sonnet 4.5（人工校验一致率：方案存在性 97.5-100%，误解识别 84.6-93.3%，重心判断 74.2-79.8%）。
