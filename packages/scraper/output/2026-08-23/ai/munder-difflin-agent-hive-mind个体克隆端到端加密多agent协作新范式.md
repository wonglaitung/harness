## 技术定义 (What)
Munder Difflin 将每个团队成员的 CLI Agent（支持 Claude Code、Codex、Gemini CLI、Qwen、Antigravity 等 12 种）包装成该成员的 "数字克隆"。克隆运行在本地机器上，共享该成员的工作流、工具和记忆。克隆之间通过 X25519/AES-256-GCM 端到端加密通道自动通信——可以请求帮助、交接任务、分享上下文。

## 行业痛点 (Why)
现有 Agent 工具全是 "单人单 Agent" 模式。真实工作场景中，开发者被阻塞等设计 token、PM 半夜需要了解计费服务状态、设计师需要审计设计系统一致性——这些跨角色阻塞都依赖人工传递上下文。Agent 再好也只能服务一个人，无法自动跨团队协作。

## 旧范式 vs 新范式
- **旧做法**：每个开发者独立使用 Claude Code/Codex，遇到阻塞在 Slack 上等人回复，上下文靠手动复制粘贴
- **新做法**：Jim 的克隆被阻塞→自动 E2E 加密请求 Pam 的克隆→Pam 的克隆返回 design tokens→Jim 的克隆继续 PR。整个过程在凌晨自动完成，PR 早上已 open

## 生产力影响 (How)
- **消除跨时区阻塞**：克隆在夜间自动互相解阻塞，早上看到的是完成的线程
- **角色全覆盖**：不仅是开发者——设计师（审计设计系统）、PM（同步文档/看板）、销售（CRM 跟进）都有克隆
- **知识复利**：每次新成员加入，克隆自动继承整个组织的共享知识库
- **隐私即架构**：本地优先+E2E 加密，代码/密钥/个人上下文永不出机器

## 采用成本
- Solo 本地：完全免费开源 MIT，使用已有 Agent 订阅
- Cloud+Network：可选付费（沙箱 VM + 加密网络）
- 学习曲线低：一键安装，自动捕获工作流

## 风险/局限
- 刚发布，缺乏生产环境验证
- 依赖底层 CLI Agent 的能力——克隆不会比它所包装的 Agent 更强
- 安全模型依赖用户正确理解 "共享 vs 个人" 知识边界
- Cloud 模式下需要信任沙箱 VM 提供商
