## 技术定义 (What)
Apache Maka 是一个本地优先的 AI Agent 工作空间。其核心创新在于 Runtime Event Log——Agent 的模型消息、工具调用、工具结果、权限决策和终止事件全部记录为 append-only 日志。桌面 UI、终端 TUI 和 CLI 都只是该日志的「视图」，不是数据的唯一副本。这意味着：会话可恢复、分支可创建、历史可搜索、上下文可裁剪而不丢失证据。

## 行业痛点 (Why)
当前 Agent 框架的状态管理存在根本问题：
1. Chat 对话被视为唯一真相源——一旦上下文窗口溢出/压缩，之前的细节就丢失了
2. 工具输出巨量数据塞入上下文窗口，Agent 被迫遗忘早先的决策
3. 没有可审计的执行记录——Agent 做了什么、为什么做、被拒绝了什么，全部散落在日志中

## 旧范式 vs 新范式
- **旧做法**：Agent 会话 = Chat 消息列表。压缩 = 丢失信息。无分支、无恢复、无可审计记录。
- **新做法**：Agent 会话 = Append-Only Event Log。UI/Chat = 日志的物化视图。压缩 = 从视图中省略旧数据但保留在日志中。支持分支、恢复、搜索、审计。

## 生产力影响 (How)
- **可恢复性**：Agent 崩溃后可以从日志恢复，不只是重试而是继续
- **可审计性**：每条决策都有完整溯源——模型说了什么、工具返回了什么、权限被批准还是拒绝
- **可分支性**：从任何 Turn 创建分支，探索替代路径
- **上下文效率**：可以从提示中省略旧工具输出但不删除证据

## 采用成本
需从源码构建；目前仅 macOS Apple Silicon 桌面端；Windows 为预览版；Linux 待支持。学习曲线中等——需理解事件日志架构。Apache 2.0 许可证。
