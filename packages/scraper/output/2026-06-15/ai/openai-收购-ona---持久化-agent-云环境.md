# OpenAI 收购 Ona - 持久化 Agent 云环境

## 技术定义 (What)
OpenAI 于 2026 年 6 月宣布收购 Ona，将其安全云执行和编排技术整合进 Codex 生态，让 AI Agent 在客户云环境中持续工作，超越单一设备或会话限制。

## 行业痛点 (Why)
- Codex 最有价值的工作跨越数小时或数天，而非数分钟
- 用户无法在关闭设备后继续任务
- 企业部署 Agent 需要安全、治理、审计能力
- Agent 需要持久化环境访问工具、系统和上下文

## 旧范式 vs 新范式
- **旧做法**：Agent 绑定单一设备或活跃会话，设备关闭任务中断
- **新做法**：Agent 在客户云环境中持久运行，用户可随时连接检查进度、提供指导、决策和审查结果

## Ona 的核心能力
- **200 万开发者**已在安全、可复现的云环境中工作
- **Customer-controlled execution**：Agent 在组织自己的云环境运行
- OpenAI 提供智能和编排层
- 组织控制：运行位置、访问范围、凭证范围、活动日志、审查流程

## 企业部署价值
1. **安全边界**：数据不出企业云环境
2. **治理合规**：完整的活动日志和审计轨迹
3. **持续执行**：笔记本电脑关闭后任务继续
4. **控制权**：客户控制基础设施、数据和安全边界

## 生产级 Agent 需求
| 需求 | Ona 提供的能力 |
|------|---------------|
| 运行位置控制 | Customer-controlled execution |
| 访问范围限制 | Credentials scoping |
| 活动日志 | 完整审计轨迹 |
| 审查流程 | Work review gates |

## 生产力影响 (How)
- **工程团队**：安全承担软件生命周期持续工作（测试、修复、现代化、漏洞修复）
- **企业组织**：自信部署 Agent 到生产工作流
- **用户**：委派更雄心勃勃的工作，无需保持在线

## 采用成本
- 时间：收购待监管批准，关闭后整合
- 成本：Codex Enterprise 订阅（Ona 能力将整合进 Codex）
- 企业部署：需云环境配置和安全策略定义
