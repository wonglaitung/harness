# Scorer-Driven Training-Free Behavior Steering（打分器驱动的免训练行为调控）

## 技术定义 (What)
Heretic 把「修改模型行为」从一次昂贵训练，变成一次带目标函数的最优化搜索。用户声明一组对比示例 Prompt 与配套的 Scorer 插件（默认两个：拒答率 keyword_rate、KL 散度），工具在无需梯度训练的数学方法族里搜索一组行为调控参数，使目标评分最优。行为目标本身是可插拔的代码（继承 Scorer 抽象基类，只需实现 get_score），因此「减少废话」「减少幽默」「降低谄媚」「改情绪倾向」「缩短回答」都只是换一个 TOML 配置 + 一个 scorer。

## 行业痛点 (Why)
微调/对齐是只有掌握大规模算力的公司才能做的事。普通开发者只能「运行」模型，无法「修改」模型——想压低某个行为倾向就得训 LoRA、造数据集、调超参，一下午起步甚至几天。而多数行为需求（少一点免责声明、少一点 AI 腔、短一点）根本不需要重训权重。

## 旧范式 vs 新范式
- **旧做法**：行为修改 = 训练问题。要么做 SFT/DPO 重训权重，要么手工调 system prompt（脆弱、占用上下文、易被绕过）。社区曾用「abliteration」做拒答抑制，但需理解模型内部结构、手工定位方向向量，且难以泛化到非拒答类行为。
- **新做法**：行为修改 = 声明式最优化问题。配置文件声明目标（用哪个 scorer、权重多少），Scorer 插件是可插拔的代码（拒答率、KL 散度，以及社区贡献的任意评分函数），工具自动搜索调控参数。零训练、消费级显卡、可量化（KL 散度约束保证不把模型改坏）。输出直接保存/上传 HuggingFace/跑 MMLU-GSM8K 验证一条龙。

## 生产力影响 (How)
把「模型行为定制」从 ML 工程师专属能力下放为普通开发者的配置项。RTX 3090 上 Qwen3-4B 约 30-40 分钟完成一次行为改造，支持 bnb_4bit 在线量化把显存需求压到与运行量化版相当。对下游应用方意味着：不必等待模型厂商调整「语气/冗长度/拒答边界」，可自行生成符合产品调性的模型变体，并用 KL 散度作为「改动幅度」的度量。

## 采用成本
低。pip install heretic-llm，一行命令。无需理解模型内部。学习成本集中在「如何写一个好的 Scorer」——但要跑默认的拒答抑制，零学习成本。注意 Heretic 1.x 配置与 2.x 不兼容，需迁移。
