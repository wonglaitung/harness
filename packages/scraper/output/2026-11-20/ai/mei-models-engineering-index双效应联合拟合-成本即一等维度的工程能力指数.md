# Mei — Models Engineering Index（双效应联合拟合 + 成本即一等维度的工程能力指数）

## 技术定义 (What)
Mei 不再对 benchmark 分数做算术平均，而是把「模型效应」和「benchmark 效应」放进同一个统计模型里联合拟合（类似 IRT/双向固定效应），从而让一个模型不会因为只跑简单 benchmark 而被奖励、也不会因为缺考部分 benchmark 而被惩罚；最后把指数重标定为均值 50、标准差 10。关键扩展在于：cost（每次 benchmark 运行成本）和 token 用量用同样的方式在对数尺度上联合拟合，与性能并列展示，并以「典型模型 = 1×」为基准做相对化。

## 行业痛点 (Why)
工程类 benchmark 高度碎片化：Cognition、Cursor、Laude Institute、Vals AI 各测各的模型子集，横比时只能看单一榜单的绝对分。更严重的是「性能榜」和「成本榜」分离，读者无法判断某个模型的高分是否用 8 倍成本换来。算术平均既混淆了「题目难度」和「模型能力」，也把成本这个一等决策变量挤到了脚注里。

## 旧范式 vs 新范式
- **旧做法**：看单榜分数（SWE-bench X% / 某榜 Y%），成本另开一个网页比较；跨榜拼表时默认「各榜可比」，缺考项直接留空，于是样本覆盖率不同的模型被当成同一个尺子上量的。
- **新做法**：用联合拟合把「模型能力」与「题目难度」解耦成一个 latent index，缺考不再导致偏差；同时把 cost 与 token 作为与性能并列的拟合维度，用对数尺度折叠成相对倍数，最终呈现为「性能–成本」「性能–token」双投影散点。评估的产出单位从「一个分数」变成「一个可辩论的坐标点」。

## 生产力影响 (How)
让「该给这个任务配哪个模型」变成二维取舍而非一维排名。示例：6.2 Astra 得分 61.5、成本 1.3×、token 0.29×；6.2 Sol 得分 55.9 但成本仅 0.37×、token 0.31× —— 差距 5.6 分换 3.5 倍成本，是否值得一眼可判。这对 Agent 类长任务尤其关键，因为 token 用量会直接放大到账单。

## 采用成本
零接入成本（纯网页查看 + GitHub 开源源）。但作为评估方法要自建时有隐性成本：需要足够多模型 × benchmark 的交叉矩阵才能拟合出稳定效应，且当前无误差棒、benchmark 等权、结果未独立复现。
