# Agent Workday & RSI Disclosure Stack（智能体工作日 + 递归自我改进披露度量栈）

## 技术定义 (What)
一套把「AI 参与 AI 研发」变成可公开度量的指标框架：把 Agent 使用量折算成「agent workday」（每 8 小时 Agent 运行 = 1 人日），并沿「投入（inputs）→ 过程（process）→ 产出（outputs）」三段式结构分层披露，同时用「Agent API 等值花费 / 人类研究员非股权薪酬」比值刻画算力与人力之间的替代关系。

## 行业痛点 (Why)
此前衡量 AI 研发加速只有模糊说法（"AI 帮我们写代码更快了"），没有可跨机构比较、可被外部审计的量化单位。RL 训练成本用 FLOPs 估算、人力投入用人数估算，两套单位无法相加，导致「递归自我改进（RSI）到什么程度」完全不可讨论。

## 旧范式 vs 新范式
- **旧做法**：用 token 消耗量、代码行数、或"研究员人数 × 时间"作为研发投入代理指标；RSI 讨论停留在定性层面，各实验室自说自话。
- **新做法**：用「agent workday」作为可换算成墙钟时间的统一单位，把 Agent 从「工具」重估为「可并行的劳动力」——报告中位数研究员日均消耗 $2,400（P90 达 $23,000），每研究员日均 5.7 个 agent workday（较年初 0.5 提升 11 倍）；同时公开「Agent 等值花费 ≈ 人类非股权薪酬的 2 倍」「内部部署仅占研究总计算量 2%」这类反直觉数字，倒逼披露口径标准化。

## 生产力影响 (How)
对 AI 团队管理者：给出可直接套用的预算与人力配比刻度（每研究员日均 Agent 预算 / 并发 Agent 数上限）；对研究者：明确 Agent 已从"辅助"变成"并行劳动力"，工作方式需围绕批量化并发重构。对投资人：新增一条判断模型公司真实研发效率的公开指标线。

## 采用成本
极低（度量层面）：需要采集 Agent 会话日志、并发峰值、模型与价格映射表；难点不在技术而在组织意愿——必须愿意公开"人类薪酬 vs Agent 花费"这类敏感比值。外部团队若要复现，需自行建立 8 小时折算与 API 等值定价基准。
