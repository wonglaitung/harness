# DaisyRose-27B — Error-Targeted Task Forging + 全异步解耦 RL

## 技术定义 (What)
两个可复用范式合体：(1) **错误定向任务锻造（Error-Targeted Task Forging）**——不做海量数据堆砌，而是先用基座模型跑每个候选任务，只保留「能稳定暴露该模型特定错误」的题目，并把难度调到解出率落在有效学习区间（约 1200 题精选自数千候选中）；(2) **全异步解耦 RL（Fully-Async Disaggregated RL）**——128 张 H200 专职跑 agent 推理生成轨迹、16 张专职训练器学习，两边互不等待，每步后把新模型推回推理池。配合 harness summarization 把长达 1M token 的单次会话折成多条轨迹参与学习。

## 行业痛点 (Why)
长时序 agent 任务的 RL 后训练有两个卡点：一是**数据贵且无效**——大量任务基座模型本来就会做，梯度信号为零；二是**同步 RL 空转**——推理要跑 1.5 小时的长会话，训练器只能干等，GPU 利用率被长尾任务拖垮。

## 旧范式 vs 新范式
- **旧做法**：海量任务 + 同步 RL：先囤万级任务数据，训练时推理与更新交替阻塞等待。算力成本高、任务普遍过于简单（无学习信号）或过难（全 0 奖励）。
- **新做法**：「任务围绕模型的错误来做」+「推理与训练物理隔离、异步并行」。用 1200 道精准弱点题、18 天、144 张 H200 完成一次有效后训练，成本比常规路径低 57%。

## 生产力影响 (How)
Terminal-Bench 4.1 pass@1 从 5.6% → 12.0%（翻倍以上）；SWE-Bench Pro v2 91.3 → 94.7；DeepSWE v1.1 42.2 → 46.2；GPQA Diamond 89.2 → 90.7。训练成本 -57%，18 天出一个专用模型。意味着「中小团队在自有算力上做领域后训练」从不可行变成可行。

## 采用成本
需自有 H200 集群（本次 144 卡）+ Miles 开源 RL 框架 + 可靠沙箱。任务锻造环节需人力逐题审核（这是主要成本，非算力）。模型 Apache 2.0 可直接商用。
