## 技术定义 (What)
ALTK-Evolve 是 IBM Research 提出的 Agent 自学习框架，核心发现颠覆直觉：**Agent 记忆不是开/关的功能开关，而是需要按模型能力校准的"剂量"**。框架自动从 Agent 历史轨迹中蒸馏行为指导方针（guidelines），在推理时按三种策略注入：全量注入（强模型）、精选检索（弱模型）、零注入（饱和模型）。

## 行业痛点 (Why)
当前 Agent 记忆实践"一刀切"：所有上下文一股脑塞进去。ALTK-Evolve 证明这在多个模型上反效果——弱模型被大量指导方针"淹死"，强模型需要全部，饱和模型无增益。没有校准的记忆反而降低准确率、增加 token 成本。

## 旧范式 vs 新范式
- **旧做法**：旧范式："Agent 记忆=更多上下文=更好性能"。堆叠对话历史、RAG 检索、全量指导方针注入。一刀切策略，不管模型大小都塞同样多的记忆。
- **新做法**：新范式："记忆是需要校准的剂量"。根据模型能力自动选择三种模式——强模型（DeepSeek-V3.2 +9.5pp TGC）用全量指导方针；弱模型（gpt-oss-120b +16.1pp TGC）用精选检索，token 仅增 5%；饱和模型（GLM-5 0pp）跳过记忆注入。

## 生产力影响 (How)
对开发者最大价值：(1) 零成本接入——不更新权重、不人工标注；(2) 自动发现"该不该给记忆、给多少"；(3) 弱模型精选检索模式：+16.1pp 任务完成率仅 +5% token——性价比最高路径。

## 采用成本
- **时间**：一次轨迹采集+蒸馏（分钟级）
- **金钱**：token 增量 5%-50%，prompt caching 可进一步降低
- **学习曲线**：低，即插即用

## 采用案例
- **gpt-oss-120b**：curated retrieval 模式，TGC 从 39.9% → 56.0%（+16.1pp），仅 +5% tokens
- **DeepSeek-V3.2**：full guideline set 模式，TGC 从 79.8% → 89.3%（+9.5pp），SGC 从 64.3% → 80.4%（+16.1pp）
- **Claude Opus 4.6 / GPT-5.5**：full 模式轻度增益（+4.1/+2.9pp）
- **GLM-5 (745B MoE)**：饱和模式，零增益——"不给记忆反而省钱"

## 风险/局限
- 仅 AppWorld 环境验证，泛化到其他 Agent 任务待确认
- 模型能力随时间变化，需重新校准
- 剂量边界：多少指导方针算"太多"尚无精确公式
