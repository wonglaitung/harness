## 技术定义 (What)
输入非结构化程序状态，输出 schema 预先定义的、带校准概率的类型安全结构化值，由代码直接消费。与 LLM 的本质区别在于：输出不是可自由的字符串，而是受限的、带置信度的决策值。

## 行业痛点 (Why)
LLM 聊天早已超人，但自动化迟迟未落地——自由字符串需解析校验、可能幻觉、置信度不可靠、串行生成延迟 3~329 秒，无法以高确定性和低延迟嵌入生产软件。

## 旧范式 vs 新范式
- **旧做法**：LLM + RLHF 优化文本，逐 token 串行生成字符串，外部解析+校验，3~329 秒
- **新做法**：RLCD 优化"校准决策"，并行采样输出概率分布，类型安全值 + 置信度，70~500ms

## 生产力影响 (How)
AI 成为"智能 if-语句"直接嵌入代码：分类/路由/打分/抽取/分支；PB 级数据 map-reduce；实时应用；护栏与 LLM 输出验证。

## 采用成本
低：OpenAI 兼容 API + adapter，需重新设计哪些决策适合结构化。

## 采用案例
- 尚无外部公开案例（早期访问），创始人 OpenAI 背景 + HN 636 分验证。

## 风险/局限
- 放弃字符串生成，不适用于需要自由文本（聊天、代码生成）的场景
- 定价可持续性未长期验证；workflow eval 由模型能力团队构建，或存偏差
