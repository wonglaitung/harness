# BotPsy — Sub-Billion Agentic Model（亚十亿参数专用 Agent 模型）

## 技术定义 (What)
0.8B 参数、专为 function calling 与 Agent 工作流训练、可端侧部署的"个人助理"模型。核心命题不是"把小模型做大"，而是"承认大多数 Agent 任务不需要前沿智能"，于是用专用训练在一个数量级更小的参数预算上换取同等甚至更好的工具调用可靠性。

## 行业痛点 (Why)
前沿云模型的运营成本波动不可控，且第三方供应商可随时修改、拒绝或下线访问权限——这是供应链风险而非单纯成本问题。同时，大量日常 Agent 任务（查资料、订行程、控制设备、读文件、管日历）根本用不到前沿级智能，用 400B 模型跑一个"帮我查天气"是巨大的算力浪费。而现有的小模型在工具调用上普遍不可靠：不知道何时不该调工具、多轮对话中丢失策略约束。

## 旧范式 vs 新范式
- **旧做法**：默认用前沿云模型做 Agent 大脑，小模型只是"能力不足时的妥协"。小模型在 Agent 场景被视为不可用——因为它们在 BFCL/τ-bench 这类工具调用基准上分数低到无法上线，且不会拒绝不存在的工具（幻觉调用）。
- **新做法**：端侧专用 Agent 模型作为独立品类。用针对性训练把 0.8B 模型的 Agent 能力翻倍（BFCL v4 从 23.4 → 44.0，τ-bench 23.2 → 51.5），在全部六项工具调用基准上击败 ≤1.2B 级对手，并在五项上击败 2.5 倍大的 Qwen3.5-2B-Think。关键不是分数，而是"知道自己不该做什么"：幻觉测试 86.1 分（全部参测模型最高），说明小模型可以通过训练获得"拒绝调用"的判断力——这是 Agent 可靠性的真正瓶颈。

## 生产力影响 (How)
对开发者意味着 Agent 推理成本可以按任务难度分层：低/中难度任务走 0.8B 端侧（零边际成本、零延迟、数据不出设备），只有高难度才上云。同时消除供应商下线风险——权重在手，模型不会某天消失。隐私敏感场景（医疗、法务、个人数据）第一次有了"能力够用且完全本地"的选项。

## 采用成本
低。safetensors 权重 + GGUF（bf16/Q8/Q4）双格式发布，Q4 量化后可在普通端侧设备运行，现有 llama.cpp / Ollama 链路直接加载。基座为 Qwen3.5-0.8B，生态兼容。学习成本几乎为零，主要是需要接受"它会在高难度任务上犯错"的边界——官方明确声明不适用于高风险场景。
