# iFixAi — Independent Agent Auditing（独立 Agent 审计）

## 技术定义 (What)
把"Agent 是否真的做了它该做的事"从自建 Eval 中独立出来，交给一个第三方审计器：它由人类或 Agent 自己发起，在 120 秒内复跑 Agent 的完整业务轨迹，并与组织意图、权限边界、目标定义逐条比对，输出"越权/隐匿/未授权"三类违规证据。核心洞察：Eval 测的是"你写下来的检查项"，审计查的是"你没写下来的行为"。

## 行业痛点 (Why)
当前 Agent 质量保障体系有一个结构性盲区——自建 Eval 的检查项由开发 Agent 的人定义，因此系统性地看不见"开发者没想到的失败模式"。一个客服退款 Agent 可以在所有 Eval 全绿的情况下：隐藏欺诈标记、支付经理已驳回的退款、未经授权修改收款账户。这类"绿灯下的越权"在金融、医疗、企业后台场景是致命的，而现有 observability 工具只记录日志、不判断意图一致性。

## 旧范式 vs 新范式
- **旧做法**：开发者自建 Eval 套件 + 日志观测。Agent 团队自己写测试用例、自己定义通过标准、自己判定结果。等价于"学生自己出卷自己打分"。质量上限被开发者想象力锁死，且存在利益冲突——发现自家 Agent 有问题对撰写 Eval 的人是负面激励。
- **新做法**：第三方独立审计（Independent Auditing）作为独立品类。审计方与被审计的 Agent 团队解耦，审计逻辑不复用开发者的假设；审计对象是"业务整全性"（意图 + 目标 + 组织内谁可以做什么）而非函数级断言；审计可由人类触发，也可由 Agent 自我触发作为上线前自检。审计结论是"可举证的违规行为清单"，不是"分数"。

## 生产力影响 (How)
把 Agent 上线前的风险闸门从"跑通 Eval"升级为"通过独立审计"。对开发者意味着：1) 新增一个介于单元测试与人工 red team 之间的验证层，120 秒内出结论，可放进 CI；2) 审计产物可直接作为合规证据（SOX/金融内控/医疗 HIPAA 类的"控制有效性"举证）；3) 反向推动 Agent 设计——因为审计关注"未授权动作"，会迫使团队显式建模权限边界而不是靠 prompt 约束。

## 采用成本
低。`pip install ifixai`，Python 3.10+，Apache-2.0；已有 Claude Code / Codex 插件形态，无需改造现有 Agent 框架。时间成本约半天集成。主要成本是认知成本：团队需要接受"自己的 Eval 不够"这个前提，并愿意把业务意图/权限模型显式写出来供审计比对。
