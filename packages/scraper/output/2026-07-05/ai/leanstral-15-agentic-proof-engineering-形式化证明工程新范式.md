## 技术定义 (What)
Leanstral 1.5 是 Mistral 发布的 119B 总参数/6B 激活参数的 MoE 模型，专门为 Lean 4 形式化证明工程训练。它不仅能自动证明数学定理，还能作为代码 Agent 在真实文件系统中运行——编辑文件、执行 bash 命令、调用 Lean 语言服务器——实现"Agentic Proof Engineering"：自主完成从定理陈述到证明验证的全流程。

## 行业痛点 (Why)
形式化验证长期停留在学术层面，无法应用于真实代码库。传统方法需要领域专家手动编写证明，成本极高。现有 AI 证明器要么只能处理竞赛级数学题，要么无法与真实开发环境交互。代码 Bug 的发现仍依赖测试和模糊测试，无法覆盖深层逻辑错误。

## 旧范式 vs 新范式
- **旧做法**：形式化验证由专家手动编写证明，仅适用于关键系统；Bug 发现依赖测试/fuzzing，无法证明代码正确性
- **新做法**：AI Agent 自主在文件系统中导航，自动推断代码意图、生成正确性属性、尝试证明或证伪，形成"推断意图→生成属性→证明/证伪→发现Bug"的闭环

## 生产力影响 (How)
- **代码安全**：自动发现测试和 fuzzing 遗漏的深层 Bug（实测发现 5 个未知 Bug）
- **成本革命**：PutnamBench 每题约 $4，对比 Seed-Prover $300+/题，成本降低 75 倍
- **证明民主化**：6B 激活参数即可在消费级硬件运行，Apache-2.0 开源

## 采用成本
- **计算**：6B 激活参数，消费级 GPU 可运行；长证明需 4M token 预算
- **学习曲线**：需了解 Lean 4 基础，但 Agent 模式大幅降低门槛
- **集成**：通过 HuggingFace 和免费 API 即可使用

## 采用案例
- **AVL 树时间复杂度证明**：2.7M token + 22 次压缩，自主完成 O(log n) 插入/删除复杂度证明
- **varinteger 库 Bug 发现**：自动发现 zigzag 解码中 Std.U64.MAX 溢出 Bug，测试和 fuzzing 均未覆盖
- **FLTEval**：费马大定理仓库实际 PR 级别证明工程，pass@8 达 43.2%

## 风险/局限
- 长证明消耗大量 token（4M token/题），成本仍需优化
- 主要针对 Lean 4 生态，其他形式化语言（Coq、Isabelle）暂不支持
- Bug 发现管线依赖 Aeneas（Rust→Lean 翻译器），语言覆盖有限
- miniF2F 已饱和，但真实世界复杂系统的证明仍具挑战
