## 技术定义 (What)
Huzzah 将伪代码（pseudocode）作为**持久化的权威源码**（`.hz` 文件），真实代码作为 AI 生成的产出物。当开发者修改伪代码并保存时，Huzzah 捕获 diff 并将其作为 prompt 发给 LLM，LLM 重新生成受影响的源代码。核心公式：**Pseudocode → Diff → Regeneration**，而非传统的 Prompt → Code。

## 行业痛点 (Why)
2026 年编码 Agent 已成熟到可替代手动编程，但开发者陷入"提示词疲劳"：
1. Prompt 被丢弃，人类意图无可靠记录
2. 自然语言指令是命令式的（描述变更），不是声明式的（描述系统）
3. 自然语言含大量社交性冗余，信息密度低

## 旧范式 vs 新范式
- **旧做法**：用长文本 prompt 描述每一步代码变更 → Agent 生成代码 → prompt 被丢弃，意图丢失
- **新做法**：伪代码是系统设计的权威表达 → 修改伪代码触发 diff → 源码自动再生 → 伪代码永远留存

## 生产力影响 (How)
- **伪代码即文档**：人类写的是设计意图，天然可读
- **语言无关**：同一伪代码可编译为多种语言实现（CRDT 等复杂算法一次性编写）
- **Token 大幅节省**：伪代码信息密度远高于自然语言
- **思维参与感**：伪代码让开发者感觉在"设计"，而非"吩咐"

## 采用成本
- 学习曲线：低（工程师天然会写伪代码）
- 适配成本：仅适合新项目，存量代码库效果受限
- 领域专家依赖：缺乏领域知识时仍需要自然语言

## 风险/局限
- 跨文件依赖表达困难
- LSP 类型支持缺失（可生成但不原生）
- 大规模项目的可行性未验证
- 代码运行在 Web Worker 沙箱，非生产级安全
