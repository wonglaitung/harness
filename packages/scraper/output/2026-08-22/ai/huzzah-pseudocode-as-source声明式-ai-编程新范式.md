## 技术定义 (What)

Huzzah 是一个实验性编辑器，用 **伪代码文件** 替代 **AI 聊天**。开发者创建 `.hz` 文件，用伪代码描述软件意图；保存时 Huzzah 自动生成实际代码（JavaScript）。修改伪代码后，Huzzah 捕获 diff 并仅重新生成受影响部分。

```
// fizz_buzz.hz — 伪代码
function fizzbuzz(N) {
  loop 1..N
    if num % 15 == 0 → "fizzbuzz"
    elif num % 3 == 0 → "fizz"
    elif num % 5 == 0 → "buzz"
    else → num
}
```

## 行业痛点 (Why)

2026 年前几个月，AI 编程 Agent（Claude Code / Codex / Cursor）已经好到无需手写代码。但开发者遭遇了"天花板"——长期写英文自然语言 prompt 令人极度疲劳。核心问题：

1. **意图丢失**：Prompt 被丢弃，代码无法区分是人类设计还是 AI 生成
2. **浪费 Token**：自然语言中大量词汇仅用于社交而非信息传递
3. **缺乏控制感**：开发者感觉失去了对代码的"设计权威"

## 旧范式 vs 新范式

- **旧做法**：Chat → Prompt（自然语言/命令式/瞬态）→ AI 修改代码 → Prompt 丢失
- **新做法**：`.hz` 文件（伪代码/声明式/持久化）→ AI 单向生成代码 → 伪代码保留为文档

## 生产力影响 (How)

- Token 消耗降低 5-10×（伪代码比自然语言紧凑）
- 人类意图天然成为开发者文档
- 同一份伪代码可生成 Python / TypeScript / Rust 实现
- 保留设计感和专业掌控力

## 采用成本

- **时间**：有编程经验者 1 小时内上手
- **金钱**：开源免费（MIT），仅需模型 API 费用
- **学习曲线**：低（伪代码是开发者自然语言）
- **局限**：目前仅适合新项目；跨文件依赖处理待验证

## 风险/局限

- 实验阶段，未经过生产验证
- 大规模项目的可行性待验证
- 跨文件依赖难以表达
- LSP 功能缺失（可生成但尚不支持）
- 不适合缺乏领域知识的开发者
