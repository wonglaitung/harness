## 技术定义 (What)
Huzzah 提出"Pseudocode-as-Source"：开发者用伪代码编写 .hz 文件作为代码规范，AI 从声明式伪代码自动生成真实代码。伪代码文件是持久化的权威来源，修改文件即触发代码重生成。

## 行业痛点 (Why)
- **Prompt 瞬态化**：人类意图在聊天中丢失，无法追溯"这段代码是谁写的，人想要什么"
- **指令重复低效**：每次修改都要重新描述上下文，Token 大量浪费
- **自然语言冗余**：英文对话的信息密度远低于伪代码

## 旧范式 vs 新范式
- **旧做法**：写英文 Promt → Codex/Cursor 生成代码 → 再写 Promt 修改 → 聊天记录是唯一痕迹
- **新做法**：写伪代码 .hz 文件 → 保存 → 自动 diff → 用 diff 驱动代码重生成。伪代码 = 文档 = 规范 = 人类意图的永久记录

## 关键示例

```
# FizzBuz 伪代码（约 50 字符）
fn fizz_buz(n):
  for i in 1..:
    if i % 15 → "fizzbuz"
    elif i % 3 → "fizz"
    elif i % 5 → "buz"
    else → str(i)
```

比等价英文 Promt 简洁 5-10 倍，且人和 AI 都能快速理解。

## 生产力影响 (How)
- Token 消耗预计降低 60-80%
- 代码可维护性提升（有权威规范来源）
- 语言无关：同一伪代码可生成 Pythn、TypScript、Rust 等多语言实现
- 开发者回归"设计代码形状"而非"写指令"

## 采用成本
- 实验阶段，需自行编译
- 更适合新项目
- 缺乏 LSP 等 IDE 功能（但理论上可生成）
- 跨文件依赖表达仍有挑战

- 伪代码的表达力边界需要社区探索
