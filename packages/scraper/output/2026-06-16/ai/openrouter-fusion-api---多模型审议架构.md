## 核心架构

```
用户提示
   ↓
[专家小组] (并行)
├─ Claude Opus 4.8 + Web Search
├─ GPT-5.5 + Web Search
├─ Gemini 3 Flash + Web Search
└─ 其他模型...
   ↓
[法官模型] (仲裁)
├─ 分析共识（consensus）
├─ 识别矛盾（contradictions）
├─ 标记遗漏（partial coverage）
├─ 提取独特见解（unique insights）
└─ 指出盲点（blind spots）
   ↓
结构化分析 JSON
   ↓
[最终回答]
```

---

## 技术定义

**Fusion = Multi-Model Deliberation + Structured Analysis**

- **专家小组**：1-8个模型并行运行，每个配备 web_search + web_fetch 能力
- **法官仲裁**：接收所有专家输出，生成结构化对比分析
- **递归保护**：自动拒绝嵌套 Fusion 调用，保持单层审议

---

## 关键创新

### 1. 结构化共识分析
```json
{
  "consensus": ["模型一致同意的观点（高置信度）"],
  "contradictions": ["模型间的矛盾点"],
  "partial_coverage": ["部分模型覆盖的要点"],
  "unique_insights": ["单模型独有见解"],
  "blind_spots": ["所有模型遗漏的盲点"]
}
```

### 2. 预设面板
- `general-high`：最强全能力量（默认：Claude Opus + GPT-latest + Gemini Pro）
- `general-budget`：快速低成本版
- 可自定义专家组合

### 3. 智能调用
- 模型自行判断何时需要"审议"
- 简单问题直接回答，复杂问题触发 Fusion

## 成本分析

### 推理成本
- 单次 Fusion = 专家数量 × 单模型成本 + 法官成本
- 示例：3专家 + 1法官 ≈ 4× 单模型调用成本
- 每个专家自动配备 web_search（额外 token）

### 延迟
- 专家并行：~单模型时间
- 法官串行：额外 1-2 秒
- 总延迟：比单模型慢 20-50%

## 使用示例

```typescript
// 快速使用
const response = await openrouter.chat.send({
  model: "openrouter/fusion",
  messages: [{ role: "user", content: "碳税的利弊分析？" }]
});

// 自定义专家小组
{
  model: "openrouter/fusion",
  plugins: [{
    id: "fusion",
    analysis_models: [
      "~anthropic/claude-opus-latest",
      "~openai/gpt-latest",
      "~google/gemini-pro-latest"
    ],
    model: "~anthropic/claude-opus-latest"  // 法官
  }]
}
```

## 风险与局限

1. **成本敏感**：不适合高频、低风险场景
2. **并非万能**：如果所有专家模型有相同偏见，仍然出错
3. **延迟约束**：实时交互场景体验下降
4. **法官依赖**：法官模型质量决定最终输出
