# OpenRouter Fusion

## 技术定义 (What)
OpenRouter 推出的多模型审议系统，通过并行调用多个顶级模型（Claude Opus、GPT、Gemini Pro），由 Judge 模型对比分析所有响应，输出结构化的共识、矛盾、盲点报告，最终由主模型综合生成高质量答案。

## 行业痛点 (Why)
单一模型的局限性：1）视角单一（可能遗漏重要论点）；2）幻觉风险（无交叉验证）；3）复杂问题准确性不足（尤其是需要多角度分析的任务）；4）用户难以判断何时该信任模型输出。

## 旧范式 vs 新范式
- **旧做法**：用户选择单一模型（如 Claude 或 GPT），模型独立生成答案。如果答案不满意，用户需要手动换模型重试，对比结果，自己判断哪个更好。无结构化的对比分析。
- **新做法**：模型自动决定何时需要多模型审议（通过 tool calling）。Panel（1-8个模型）并行回答，Judge 模型生成结构化分析（共识、矛盾、部分覆盖、独特见解、盲点），主模型综合后输出最终答案。整个过程自动化、可追溯、成本可控。

## 生产力影响 (How)
对开发者的影响：1）提升复杂任务准确性（研究、决策、政策分析）；2）降低幻觉风险（多模型交叉验证）；3）结构化输出便于程序化处理（JSON 格式的共识/矛盾/盲点）；4）成本权衡透明（用户可选择 high/budget preset）。

## 采用成本
使用成本：每次 Fusion 调用 = Panel 模型费用 + Judge 模型费用 + 主模型费用。对于复杂任务（如政策分析、学术研究），成本增加 3-8 倍，但准确性和全面性显著提升。集成成本：仅需在 OpenRouter API 请求中添加 plugins 配置。
