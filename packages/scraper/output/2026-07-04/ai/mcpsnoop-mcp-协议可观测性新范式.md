## 技术定义 (What)

mcpsnoop 是"MCP 协议的 Wireshark"——一个透明代理，坐在 AI 客户端（Claude Desktop、Cursor、Claude Code）和 MCP 服务器之间，实时捕获并展示每一个 JSON-RPC 帧。它不是作为第二个客户端连接（如官方 MCP Inspector），而是嵌入真实数据路径中，因此能看到客户端真正发出和未发出的调用。

## 行业痛点 (Why)

MCP 生态正在爆发式增长，但开发者调试 MCP 工具时面临"黑箱问题"：工具静默不被调用、参数不匹配、调用挂起时，只能靠 tail 日志猜测。官方 Inspector 作为独立客户端连接，永远看不到真实客户端↔服务器间的流量。这是 MCP 从实验走向生产的关键瓶颈。

## 旧范式 vs 新范式

- **旧做法**：使用 MCP Inspector 作为旁路客户端观察，或在服务器代码中打断点、tail 日志文件猜测问题
- **新做法**：透明代理拦截真实流量，实时 TUI 展示所有 JSON-RPC 帧，支持过滤、回放、能力检查、挂起检测

## 生产力影响 (How)

1. **MCP 开发调试效率提升 10x+**：不再需要猜测工具为何不被调用
2. **回放功能**：对捕获的调用一键回放到隔离服务器实例，最快迭代循环
3. **能力检查**：一键查看客户端和服务器握手时协商的能力，排查兼容性问题
4. **挂起检测**：实时计时器标记卡住的调用，一目了然

## 采用成本

- **时间**：5 分钟（wrap 你的 server 命令即可）
- **金钱**：免费，MIT 开源
- **学习曲线**：极低——零配置，无需指定 socket 路径或启动顺序
- **依赖**：Go 单二进制，无运行时依赖

## 采用案例

- **MCP Server 开发者**：调试工具调用不触发、参数不匹配问题
- **AI Agent 框架集成者**：验证 Agent 与 MCP Server 的握手和能力协商
- **企业 MCP 部署**：审计和监控生产环境中的 MCP 流量

## 风险/局限

- 当前 pre-1.0，API 可能变化
- 仅支持 stdio 和 streamable-HTTP 传输模式
- 安全注意：代理可看到所有流量，不宜用于敏感数据场景不加保护
- Show HN 分数尚不算高，社区验证需更多时间
