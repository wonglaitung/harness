## 技术定义 (What)
pxpipe 是一个本地代理，将LLM请求中的密集文本内容（系统提示、工具文档、历史记录）渲染为紧凑PNG图片后再发送。核心洞察：图片的token成本由像素尺寸决定，而非内容量——密集内容在图片中约3.1字符/image-token vs 文本中1字符/text-token，实现约7倍token压缩。

## 行业痛点 (Why)
LLM长上下文场景（如Claude Code编程）中，系统提示+工具文档+历史记录占据大量input token，导致：1）成本高昂（单session可达$42）；2）上下文窗口快速耗尽（96%满载）；3）被迫compaction丢失信息。

## 旧范式 vs 新范式
- **旧做法**：所有内容以纯文本发送，token成本与字符数1:1，长session被迫压缩或截断
- **新做法**：密集文本渲染为图片，token成本降至1/7，模型通过视觉能力"阅读"图片内容，Fable 5模型阅读准确率100/100

## 生产力影响 (How)
- Claude Code session成本从$42降至$6（~85%节省）
- 上下文占用从964.5k/1M降至73.5k/1M，释放90%+上下文空间
- SWE-bench Lite 10/10通过率与纯文本持平，SWE-bench Pro 14/19 vs 15/19基本持平
- 开发者无需改变工作流，只需 `npx pxpipe-proxy` + 修改base URL

## 采用成本
- 时间：5分钟安装配置
- 金钱：开源免费，代理本地运行无额外费用
- 学习曲线：极低，一行命令启动，自动判断哪些内容适合图片化
- 风险：有损压缩——精确值（ID、hash、密钥）需保留文本格式

## 采用案例
- Claude Code编程：系统提示+工具文档25k text tokens → 2.7k image tokens
- GPT 5.6：工具定义保留JSON格式，仅冗余schema描述图片化
- SWE-bench测试：token等效成本减半，通过率持平

## 风险/局限
- **有损性**：12字符hex字符串在Opus上0/15召回，Fable 5上13/15
- **静默幻觉**：失败模式是"看似合理的错误值"而非报错
- **模型依赖**：仅Fable 5达到100%阅读准确率，Opus约93%，其他模型可能更差
- **稀疏内容反效果**：英文散文（~3.5 chars/token）图片化反而增加成本
- **精确值需手动保护**：ID、hash、密钥必须保留文本格式
