## 技术定义 (What)
LatticeDB 是一个嵌入式、单文件的属性图数据库，在一个引擎中同时支持：图遍历（Cypher 风格查询）、HNSW 向量相似度搜索（<=> 操作符）、BM25 全文检索。整个数据库就是一个可移植的单文件，像 SQLite 一样零配置运行。

## 行业痛点 (Why)
当前做 Graph RAG 需要组合 3-4 个系统：Neo4j（图）、Pinecone/Qdrant（向量）、Elasticsearch（全文）——每个都需要独立部署维护。Agent 记忆系统面临同样的问题：结构化关系、语义搜索、关键词搜索各需不同存储。

## 旧范式 vs 新范式
- **旧做法**：Neo4j + Pinecone + Elasticsearch 三个独立系统，各自部署，各自 API，数据同步困难
- **新做法**：一个单文件 `knowledge.db`，一条 Cypher 查询同时做图遍历 + 向量搜索 + 全文检索

## 生产力影响 (How)
单机/本地优先的 AI 应用开发被大幅简化。Agent 记忆系统（结构化关系 + 语义检索 + 关键词匹配）可以在一个文件中完成，无需运维多个数据库。适合本地 Agent、Graph RAG、个人知识库等场景。

## 采用成本
零基础设施成本。单文件嵌入，npm/pip install 即可。学习成本主要在于 Cypher 查询语言和图建模思维。

## 采用案例
- **Graph RAG**：知识图谱增强检索，在同一查询中组合向量相似度 + 图遍历
- **Agent Memory**：结构化的 Agent 记忆存储，支持语义和关系查询
- **本地知识工具**：单机知识库应用，全在本地运行

## 风险/局限
- 单写入者模型，不支持多进程并发写入
- 仅限单机，不适合分布式场景
- 项目非常早期，API 可能变动
- 嵌入向量使用占位 hash，生产需替换真实 embedding 模型
