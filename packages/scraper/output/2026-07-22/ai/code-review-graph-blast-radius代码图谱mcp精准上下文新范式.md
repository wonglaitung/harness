## 技术定义 (What)
code-review-graph是一个本地优先的代码智能图谱系统。它用Tree-sitter将代码库解析为AST图谱（函数、类、导入为节点，调用、继承、测试覆盖为边），存储在SQLite中。当文件变更时，通过"Blast-Radius分析"追踪所有受影响的调用者、依赖者和测试，计算出AI编码工具需要阅读的最小文件集，而非扫描整个项目。通过MCP协议向AI工具提供精准上下文。

## 行业痛点 (Why)
AI编码工具（Claude Code、Codex、Cursor等）在代码审查时反复重读大量代码，浪费token且效率低下。在大型monorepo中，一个变更可能影响27,700+文件，但实际只需阅读约15个文件。现有工具缺乏代码结构感知能力，导致AI"盲人摸象"式审查。

## 旧范式 vs 新范式
- **旧做法**：AI编码工具审查代码时，将整个项目或大段代码塞入上下文窗口，token浪费严重，审查质量随项目规模下降
- **新做法**：先构建代码结构图谱，变更时计算Blast-Radius，AI只阅读受影响的最小文件集，token使用降低38x-528x

## 生产力影响 (How)
1. **Token成本暴降**：6个真实仓库测试中，token减少38x到528x
2. **审查质量提升**：AI获得精准的依赖关系上下文，不再遗漏跨文件影响
3. **Monorepo可用**：27,700+文件项目中，审查范围从全项目缩减到~15个文件
4. **增量更新<2秒**：文件保存时自动增量更新图谱，2,900文件项目重索引不到2秒
5. **一键安装**：`pip install code-review-graph && code-review-graph install`自动检测并配置所有AI工具

## 风险/局限
- 依赖Tree-sitter解析，对非常规语法或宏密集代码可能不完整
- 首次构建大型项目需要时间（但后续增量更新极快）
- 目前主要针对代码审查场景，其他Agent工作流尚未覆盖
- SQLite存储在极大规模项目（10万+文件）下性能未验证
