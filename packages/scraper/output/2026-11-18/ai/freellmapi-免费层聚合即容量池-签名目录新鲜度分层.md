# FreeLLMAPI — 免费层聚合即容量池 + 签名目录新鲜度分层

## 技术定义 (What)
FreeLLMAPI 把 87 家厂商的免费额度（736 个模型家族 / 1,313 个免费端点）聚合成一个 OpenAI 兼容的 `/v1` 端点，合计约 **101 亿 tokens/月** 的可用推理容量。三个可命名新构造：(1) **Free-Tier Aggregation as Capacity（免费层即容量池）**——单个免费额度是玩具，堆叠起来是可用产能；路由器按请求挑最优可用模型，遇到限流自动落到下一家，并按 key 记账以不越过每家的免费上限。(2) **Signed Model Catalog Feed（签名目录流）**——模型/配额/兼容性补丁由服务端签名下发，安装实例无需 `git pull` 即可跟上「模型下线、额度变更」的周级漂移。(3) **Catalog Freshness as a Pricing Axis（新鲜度即定价维度）**——免费安装拿到 30 天延迟的快照，付费（$19/年）拿当日流；即**把「目录滞后天数」直接变成商业模式**，这在工具类产品里是罕见的切分方式。

## 行业痛点 (Why)
每家 AI 实验室都送免费额度，但单独用都是玩具：87 个 SDK、87 套限流规则、87 个可能失败的地方。手工堆叠的痛苦让这些「免费产能」事实上无法被个人开发者和小团队利用。同时免费层格局每周都在变（模型上下线、配额调整），任何硬编码的聚合器几个月就腐烂。

## 旧范式 vs 新范式
- **旧做法**：要么只用一个厂商的免费额度（容量太小），要么自己手写多厂商适配与 fallback（维护成本高，且随厂商变更持续腐烂）；模型目录硬编码在代码里，靠发新版本来跟上生态变化。
- **新做法**：把「免费层」当成一种可聚合的基础设施资源，用单一 OpenAI 兼容端点暴露；用**签名目录流**把生态漂移从「发版问题」变成「数据更新问题」，再按「目录新鲜度」而非「功能」来切分免费/付费。

## 生产力影响 (How)
对个人开发者/小团队：把每月可用推理容量从「几百万 tokens」提升到「百亿级」，足以支撑真实实验、批处理和 agent 长跑；对接成本 ≈ 改一个 base_url。对工具作者：示范了「自更新目录」这一抗腐烂模式——凡是依赖外部快速变化生态的本地工具（模型清单、定价表、provider 能力矩阵）都可照抄。

## 采用成本
低。Docker / macOS / Windows / iOS / Android 全平台分发，本地起服务后任何 OpenAI 兼容客户端直接把 base_url 指过来即可。需要自己准备各厂商的免费 key（加密存储）。
