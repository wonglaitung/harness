# HealthAdminBench

## 技术定义 (What)
斯坦福 Shahlab 发布的医疗行政 GUI 基准：135 个任务 / 1698 个子任务，跑在 4 个真实可交互门户（EMR 事前授权、拒付、DME、eFax、Payer A/B）上，覆盖事前授权、器械订单、申诉三大工作流，三档难度，多维度评分（精确状态检查 + LLM 判定临床准确性），并强调跨 run 的统计可复现性。

## 行业痛点 (Why)
此前的 Agent 基准多在合成网页或简化环境里跑，测不出「真实企业门户 + 长链条表单 + 临床文档判读」的复合难度；更关键的是，没有人量化过「给同一个基础模型套上 CUA 包装器」到底带来多少增益，以及「跑更多步」是不是就等于「更强」。

## 旧范式 vs 新范式
- **旧做法**：用通用网页导航基准（或合成沙箱）评估 Agent，用「得分」单一维度排名模型，默认步数越多代表越努力/越强。
- **新做法**：把 CUA 包装器当成独立变量：同一模型「有 CUA / 无 CUA」分开上榜，直接量化包装器带来的能力倍增；同时发布「平均步数」与「得分」的相关性，证明步数不是能力代理；再把每任务成本作为并列的评测轴（GPT-6 Luna 以 8.5 美分/任务拿下 91.8% 的 rubric 分，成本低 98%）。

## 生产力影响 (How)
给企业选型提供了真实可交互的行政工作流靶场；揭示 CUA wrapper 是当前提升 GUI Agent 能力最有效的一招（Claude Opus 4.6 从 14.8% → 36.3%，2.45 倍）；同时证明基础模型裸跑在真实门户上几乎不可用（GPT-5.4 仅 5.9%）。

## 采用成本
作为基准使用几乎零成本——4 个门户公开可访问，含 demo 登录凭据，任务 JSON 全量开源于 GitHub，可自行复现或扩展任务集。
