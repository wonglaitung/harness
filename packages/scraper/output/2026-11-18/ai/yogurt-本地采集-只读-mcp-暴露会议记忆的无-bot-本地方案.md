## 技术定义 (What)

Yogurt 是开源（MIT）本地优先会议记录应用，定位 Granola 的免费替代。它**不派 Bot 进会议**，而是录制麦克风 + 系统播放音频，用 `whisper.cpp`（Mac 上叠加 Apple SpeechAnalyzer）转写，用 `llama.cpp` 跑本地开放权重模型做摘要与问答。音频、转写、推理全部留在本机。

关键设计在对「Agent 可读性」的处理：内置本地 MCP server，但**默认关闭**；开启后仅授予**只读**权限——外部 Agent 可读会议、笔记、转写、音频与日历详情（参与者姓名与邮箱），**无法修改**。权限边界写进产品语义，而非靠 OAuth scope 拼装。

## 行业痛点 (Why)

云端会议助手（Granola / Otter / Fireflies 类）要求上传音频与转写，且常以「派 Bot 入会」方式采集——这对法务、医疗、并购场景是硬阻断。同时，即便应用本地化，Agent 生态又要求数据可读，本地应用往往被迫开放完整读写，或干脆不接入。

## 旧范式 vs 新范式

- **旧做法**：云端 + Bot 入会 + 全量同步。数据必须离开本机才能获得 AI 能力；Agent 接入 = 交出读写权限。隐私与可组合性被当作二选一。
- **新做法**：把两个决策拆开。
  1. **采集路径**改本机音频回路，彻底取消 Bot 入会这个「会议中的可见第三方」；
  2. **Agent 暴露路径**改本地 MCP + 默认关闭 + 只读语义。
  
  结果：「数据不出本机」与「Agent 能用」同时成立，最小权限是产品默认值，用户不需要理解 OAuth 就能安全。

## 生产力影响 (How)

- **受监管行业**：拿到一条可用的本地会议记忆路径。8GB 内存即可跑，无需账号，离线可用。
- **Agent 开发者**：示范了本地应用作为「只读 MCP 数据源」的标准姿态——Agent 侧无需改动即可读取结构化会议上下文（含参与者日历信息）。
- 附带能力：99 语种多语言模式、各方各说各语言、会议中途切语种、跨会议问答带来源引用。

## 采用成本

低。下载即用（macOS 14.4+ / Win10 2004+ / Ubuntu 22.04+，8GB 内存），首次下载转写与摘要模型；接入 Agent 只需在 Settings → AI apps 复制一条本地 MCP 命令。零费用、MIT、无需账号。

## 采用案例

- **Holiday Extras（同批次 OpenAI dots 客户故事）**：VP of AI 明确提到曾试用 OpenClaw 与 Hermes，但因「不放心给出太多信息」而放弃，最终选择企业环境内可信任的方案——侧面印证「本地/可控采集」是企业落地的真实门槛。
- 项目自身：Show HN 306 分，评论区集中讨论「不要 Bot 入会」与「本机转写质量是否够用」。

## 风险/局限

- **无 Bot = 录不到对方的高质量音轨**：只能录系统播放的声音，音质受扬声器/耳机路径影响，多人重叠说话时区分度弱于云服务。
- **只读 MCP 是产品承诺，不是技术强制**：Agent 读取后仍可把数据发往其自有云端模型，README 也明说 "It may send what it reads to its own online model"。只读约束的是写，不是数据外流。
- **说话人分离**依赖 Zoom/Teams/Meet 在三大平台的集成，非通用。
- 单人维护属性较强（Frigade 商业公司背书），长期维护节奏待观察。
