# CUA Agent Kit (Discover-then-Codify)

## 技术定义 (What)
CVS Health 开源的一套「先发现、后固化」工作流自动化套件：先用 OpenAI 计算机使用 Agent 按自然语言指令在真实浏览器/Windows 桌面里跑通一遍流程，录下截图、动作、目标元素与 trace；再用一个 Codex Skill 把这些录证据编译成带语义定位器的 Playwright / pywinauto 确定性代码。此后生产运行时完全不需要 LLM、不需要 API Key。

## 行业痛点 (Why)
传统 RPA 每个新流程都要人工录制/编写，成本高、易碎；而纯 CUA Agent 虽能用自然语言「自己摸索出怎么做」，但把同一套步骤每次都用模型重新推理一遍，会带来推理成本与执行不确定性——对于步骤稳定的高频流程，这是纯浪费。API 也无法覆盖应用里所有 UI 动作。

## 旧范式 vs 新范式
- **旧做法**：二选一：要么人工写 RPA/Playwright 脚本（贵、慢、难维护），要么每次运行都让 CUA 模型现场推理点鼠标（贵、每次结果可能不同、易漂移）。
- **新做法**：Agent 只当一次性的「编译器前端」：模型负责探索与理解，产出物是可被人读、可测试、可版本控制的确定性代码；LLM 在运行时被彻底移除。流程坏了时，再用 Codex 读生产 trace 做定点修复（AI 辅助维护 + 工程师评审）。即「推理沉淀为制品」，智能是一次性资本支出而非每笔运营支出。

## 生产力影响 (How)
高频流程的边际推理成本降为零，执行结果可复现可审计；把 CUA 从「每次都要付费的运行时」变成「一次性的开发工具」。对需要稳定性的企业后台自动化（发文档、转诊、授权申请）是成本模型层面的改变。CVS 披露：某生产流程一个周末清掉了积压数月的文档发送队列，另一流程每天处理数万次会诊的系统步骤。

## 采用成本
低-中。Python 3.12 + uv + 一个 OPENAI_API_KEY（仅发现阶段需要）。需要为每个目标流程写一段自然语言 prompt，并反复跑几次发现直到稳定成功；固化后的运行环境不需要任何密钥。Windows 侧需一台保持解锁的 VM。
