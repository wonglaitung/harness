## 技术定义 (What)
LFM3 是 Liquid AI 的新一代 Liquid Foundation Models，核心是**一棵从单一骨干分叉的模型树**：LFM3-1.7B-Base（22T tokens 预训练，末段 3.5T 为 agentic trace 与工具调用为主的 mid-training，上下文扩到 256K）→ 后训练出 **LFM3-1.7B（文本）、LFM3-VL-2B（文/图/视频）、LFM3-Audio-2B（文/音，出文本与语音）、LFM3-Omni-2B（全模态）**，再在其上派生 **d1-2B 与 d1-omni-2B：输出不是文本，而是校准答案（calibrated answers）**。架构为 tri-hybrid：13 层门控短卷积（kernel 7）+ 5 层 256 窗口滑窗注意力 + 6 层全局注意力，配 head-wise sigmoid 门控（可抑制量化离群值）、部分 RoPE（仅旋转最高频一半）、sandwich norm。

## 行业痛点 (Why)
端侧 Agent 要的不是更大的通才，而是"按输入类型选一个够小、够快、能微调"的专家；同时"决策"一直被当作 LLM 的用法（生成再解析），既贵又拿不到概率与置信度。而多模态家族通常各模态独立训练、各带一套编码器，端侧既塞不下也无法共享工具链。

## 旧范式 vs 新范式
- **旧做法**：一个尽可能大的通用 LLM 覆盖全部输入；决策靠 prompt 生成 JSON 再解析；多模态各自为战、编码器外购（如 SigLIP2）；端侧只能上蒸馏小模型，能力与上下文双输。
- **新做法**：单骨干 + 按模态后训练分叉，**决策成为与文本/视觉/音频并列的输出模态**；自研端侧优先编码器（视觉 164M 参数，精度匹配 Qwen3.5-2B 视觉编码器但 FLOPs 少 2.2×、比 SigLIP2 少 3× 算力；视频按帧对合成时间片，时间序列长度减半）；音频编码器全因果，可边说话边 prefill；每个模型都能单卡微调。

## 生产力影响 (How)
- 端侧：文本模型 4-bit 约 1GB，256K 上下文让 Agent 跑在设备上；8K 上下文时比同质量基线约快 25%；语音首 token 低至 50ms，LiquidCodec 在单核 M4 Max 上约 87× 实时合成并支持流式解码。
- 决策任务（客服分流、意图识别、评审打分、合规判定）：d1 直接给校准答案，带概率与置信度，可与 System One / AnyDecisionModel 生态对接，避免"生成再解析"的成本与不确定性。
- 定制：选模态 → 用自己的数据单卡微调 → 就地部署，形成闭环。

## 采用成本
- 推理：`transformers` 原生支持，另列多种推理引擎；硬件从手机、Raspberry Pi 5 到笔电/云 CPU/GPU/Hexagon NPU（架构搜索覆盖 14 种组合）。
- 微调：单卡 GPU 即可（2B 级）。
- 认知：需要从"选模型大小"切换为"选模态 + 选专家"的选型逻辑。

## 风险/局限
- 2B 级模型在复杂推理上仍无法替代前沿大模型，适用边界在端侧与专用任务。
- 六个派生模型意味着版本/维护组合爆炸，选型与升级成本上升。
- d1 的"校准答案"质量高度依赖任务分布，跨域迁移表现未公开。
- 与已成熟的小模型赛道（Phi/Gemma/Granite 小尺寸）正面竞争，生态位尚未验证。
