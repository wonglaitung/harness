## 技术定义 (What)

Dharma-AI 提出的一种 tokenizer 重建方法：不改变基础模型权重，而是围绕"每个 token 的实际服务成本"重新设计词表。核心洞见是生成一个 token 的成本约为读取一个 token 的 7.4 倍（decode 阶段受显存带宽限制），因此"在模型输出侧省下的 token"价值是"输入侧"的 7.4 倍。VocabX 同时工作在两个层次——子词层（重建领域词的切分方式）与多词层（把重复出现的整段 span 如 JSON envelope 合并为单个 "macro token"），两层用同一成本标准、各自独立预算来挑选。生产环境实测推理成本下降 77%，词表从 151,669 降到 64,767 条。

## 行业痛点 (Why)

领域特化的小模型（如 Qwen3-4B 微调成葡语作文评分器）继承了为"多语言多领域"设计的通用词表，造成双重浪费：

1. **碎片化**：领域内最高频的文本（JSON envelope、能力项名称、固定评语）被切成很多 token。同一段模型每次都要写的 span，用基础 tokenizer 要 12 个 token，用 VocabX 只要 1 个。
2. **冗余**：词表携带数万条该领域永不使用的条目，而每个生成的 token 都要对全部条目打一次分；LM head 矩阵在 Qwen3-4B 上占近 10% 参数，在 decode（memory-bound）阶段每次都要全量读一遍。

已有方案（FVT / MWT / Liquid AI in-place BPE）都按**频次**选 token，且只处理单层——恰好错过最贵的部分。

## 旧范式 vs 新范式

- **旧做法**：Tokenizer 是基础模型的固定属性，继承下来就不动。降本 = 减少 token 总数，输入输出同等对待。词表扩展按"出现频率"决定合并哪些 token。
- **新做法**：Tokenizer 是领域特化模型最大的**成本杠杆**，且在训练第一步之前就已设定。降本 = 最小化 Σ(被消除 token × 该 token 所在字段的单价)，输出侧权重 7.4×。子词重建与整段 macro token 在同一成本标准下联合优化。

## 生产力影响 (How)

在运行中的生产系统上实测推理成本降低 77%，且不换基础模型、不换训练数据、不换训练配方。这意味着：**任何已上线的领域小模型，都存在一个"零模型改动、纯 tokenizer 层"的成本优化空间**，且在 decode-heavy 的生成式任务上空间最大。对做垂直小模型落地的团队，这是被长期忽视的第一优先级优化项——比量化、蒸馏都更便宜且可叠加。

## 采用案例

- **Dharma-AI 葡语作文评分器**（Qwen3-4B）：输入作文 + 题目 + 支撑文本，输出每项能力的分数与评语的 JSON。VocabX 重建后输出层从 ~152,000 行降到 ~65,000 行，实测推理成本 -77%。

## 风险/局限

- **论文未定稿**：作者明示"数字来自论文当前版本，仍在审稿，发表前可能变化"。
- **方法论未开源**：无代码仓库，复现需自研。
- **域漂移脆弱性**：词表按单一领域的成本结构定制，一旦任务分布变化（新增输出格式、换语言），省下的成本可能反转为损失，且需重训 tokenizer + 适配权重。
- **7.4× 系数非普适**：该比值随硬件、batch size、上下文长度变化，成本模型需按自己的部署实测标定。
