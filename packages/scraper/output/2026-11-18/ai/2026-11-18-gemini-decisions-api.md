# Gemini Decisions API — 零输出 Token 的「决策评分端点」

## 技术定义 (What)

模型不生成答案，只**打分**。你传入一个共享输入（多模态，最长 256K token）和最多 1000 个问题，模型在一次前向传播中为每个问题的候选选项输出概率与置信度。三种原语：

- **noul（是/否）**：估计某条件为真的概率，可附 true/false 描述标准
- **choice（多选）**：2-255 个候选中选出赢家，返回全部归一化概率
- **score（有序评分）**：按有序 rubric 打分，返回连续加权分与各级别概率

关键工程特性：延迟几乎不随问题数增长（1→100 问基本持平）；共享输入按请求计费一次，每题只加自身的指令与标准 token；无 thinking token 波动账单，无独立 OCR/ASR 费用。

## 行业痛点 (Why)

Agent 系统的真实开销不在「难问题」，而在海量的**廉价判定**：这条消息是不是在提问？这个会话摘要有没有暴露个人信息？这个 query 该路由给哪个模型层级？哪个工具能完成这个任务？

这些任务用生成式 LLM 做，等于「用卡车送一封信」：延迟是逐 token 的，成本是逐 token 的，而最有价值的信息——**不确定性**——被压成了一句不容置疑的散文。PostHog 的原话很精准：「LLM 爱废话。问一个简单问题，得到几百字『视情况而定』。」

## 旧范式 vs 新范式

- **旧做法**：prompt 大模型 → 要求输出 JSON → 正则/json.loads 解析 → 拿到一个看似确定的字符串。为省成本自训 BERT 类小分类器，需标注数据与持续维护。置信度只能靠 logprob 黑魔法或干脆没有。
- **新做法**：声明候选集 → 单次打分 → 拿到概率分布 → 用阈值决定「直接放行 / 调大模型 / 转人工」。置信度是一等公民，阈值按「代价不对称」调节。

## 生产力影响 (How)

PostHog 的生产数据是最强的成本论据：决策模型比前沿模型便宜 444.6×、快 193.6×，因此可以**放在每个昂贵调用之前当门**。他们的 Replay Vision 流水线用两个 yes/no 问题筛选会话摘要是否含 PII：

1. 「是否点名了真实的人？」 2. 「是否包含联系方式或证件号？」
3. 任一 ≥ 0.4 → 交给 Gemini 重写并复检
4. 否则直接放行

结果：**98.7% 的请求完全跳过 LLM 调用**。另一个反直觉发现：拆成两个窄问题，误报率降到单问题方案的 1/10。

Slack bot 侧则是反向用法——只有两个问题都 ≥ 0.85 才响应（避免「未被 @ 也抢答」惹人烦）。同一技术，两种阈值方向，取决于「哪种错更贵」。

## 采用成本

- **金钱**：$0.10/1M input token，输出 $0。AI Studio 免费额度可原型验证。
- **时间**：接入 1 小时内（标准 Gemini API key + Google AI Studio 的三个 demo app 可照抄）。
- **学习曲线**：API 极简，真正的功夫在阈值工程——需要先想清楚 false positive 与 false negative 各自的业务代价。
- **迁移风险**：与既有 prompt-based 判定逻辑可并行 AB，回滚成本低。

## 采用案例

- **Gemini Notebook**：作为实时路由器，毫秒级判定意图，把日常查询延迟降 40%，深度推理模型只留给复杂任务。
- **Stitch Rapid（Google Labs）**：用它秒级生成可玩的线框流程，语音/点击编辑近乎即时生效；流程确定后一键交给完整 Stitch 深加工。
- **PostHog Replay Vision**：98.7% 请求跳过 LLM，PII 漏检率下降一个数量级（开源 PR #120387 可查）。
- **Google Search MCP 安全层**：在延迟预算内检测 MCP 工具的对抗行为与恶意内容。

## 风险 / 局限

- **校准 ≠ 准确**。0.85 的置信度仍意味着千次中约 150 次出错。它给的是「可以定价的不确定性」，不是「正确答案」。若业务无法承受任何漏检，仍需人工兜底或更高阈值 + 二次校验。
- **闭集限制**。只能回答你预先定义的选项。开放式推理、需要解释理由的任务不适用——这类任务仍交给生成式模型。
- **供应商锁定**。这是托管端点，不是开放权重；decision model 的「可自托管」优势（Jev 类方案）在此不成立。
- **阈值是产品决策，不是技术参数**。团队若没有明确的代价模型，会把它用成「看起来很科学的 if/else」。

## 谱系定位（重要）

这不是孤立出现的技术，而是「决策模型」这一品类的**基础设施化**节点。此前链条：

1. **Jev / System One Models**（typesafe.ai）提出「类型化结构化决策」概念，确立了 noul/choice/score 这套原语词汇。
2. **Hugging Face Decision Models / AnyDecisionModel** 让决策模型可开放下载、可在 Apple 端侧跑。
3. **Gemini Decisions API**（本文）把同一套原语搬上云端托管端点，加入原生多模态 + 1000 问/请求 + 零输出计费。

**范式判据**：当前两代靠「开放权重」取胜，这一代靠「机械同情 + 规模」取胜。二者不是替代关系，而是决策层的**端云双轨**。看到 noul/choice/score 这三个词出现在两家完全独立的厂商 API 中，是该概念已成为事实标准的强信号。
