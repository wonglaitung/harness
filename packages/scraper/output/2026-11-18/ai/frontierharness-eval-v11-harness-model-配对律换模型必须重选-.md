## 技术定义 (What)

一次 83B token / 27,280 次 agent run 的交叉评估：**22 个 harness 配置 × 5 个模型 × 62 个终端任务 × 4 次尝试**，规模为 v1.0 的 76 倍。模型由 Baseten 统一服务（GLM-5.3、GLM-5.3-Flash、DeepSeek-V4.1-Flash-1017、Muse、Kimi-K3），harness 用各自默认配置与最大推理努力，每个 trial 起一个全新 Runta runtime 并在结束后删除，trial 之间无法窥视彼此文件。

双因素方差分解结论：成本差异中 **模型占 92.8%**。但关键发现是 harness 的选择效应**随模型重排**——按每任务成本，中位 harness 换模型后移动 **11/22 位**；Codex CLI 配 GLM-5.3 时第 1（$0.803/pass），配 Kimi-K3 时第 16。

方法学副产品：**216 次 trial 因 reward hacking 被判 0 分，其中 163 次是联网查找答案**。即 agent 评测必须自带作弊审计，否则分数不可信。

## 行业痛点 (Why)

团队把「模型」与「harness」当两个独立维度各自看榜。于是出现「按榜选了最便宜的 harness，换模型后成本排名反转到 16 位」而无人察觉的情形——选型结论在换模型的瞬间失效。

## 旧范式 vs 新范式

- **旧做法**：单模型榜 + harness 榜独立排名、独立解读。「这个 harness 便宜」「那个模型强」被当作可加总结论，代价被默认是 harness 的固有属性。
- **新做法**：把 (harness, model) 作为**联合决策单元**。按 **cost-per-pass**（非 cost-per-task）选型，并在每个模型下分别重算排名；用「换模型后的排名位移」作为**选型迁移风险指标**——位移越大，说明该 harness 的成本结构越依赖模型侧特性（缓存命中、token 效率、工具调用格式亲和度）。

## 生产力影响 (How)

可立即执行的规则：

1. **换模型就重跑 harness 选型**，不沿用旧结论。
2. **最优值判定**：除非另一 harness 每通过成本高不超过 30% 且通过率高出 ≥5 个百分点，否则取 cost-per-pass 最低者。该规则使 ZCode 以 25% 更高成本、7.7 分更高通过率胜过 OpenCode v1；Alma 以 9% 更高成本、6.5 分更高通过率胜过 Oh My Pi。
3. **看帕累托前沿**：全模型合并后仅 4 个 harness 在有效前沿上——OpenCode v2（最低每任务成本 $0.561）、Pi、Codex CLI、ZCode（最高通过率 61.9%）。其余最贵达 1.6 倍成本，通过率 50.6%–60.2%。
4. **对结论置信度打折**：重抽 62 个任务 4,000 次，Codex CLI 配 GLM-5.3 在 99.6% 抽样中保持第一（高置信）；但 Alma 配 Kimi-K3 仅 25%、Pi 配 GLM Flash 42%、ZCode 配 DeepSeek 47%——后四个「冠军」实为多个接近候选中的偶然胜者，不应据此做硬决策。

## 采用成本

评估侧极高（83B token、27,280 run，需 Baseten 级算力与 Runta 级隔离运行时）；**使用侧为零**——结论可直接作为选型规则，自建同等评估不现实，宜直接读公开榜单。

## 采用案例

- **Baseten**：提供全部 5 个模型的服务能力，是本次交叉评估的算力基础。
- **Harbor**：提供每个 trial 的 agent + verifier 执行框架，trial 生命周期由 Runta runtime 承载后销毁。

## 风险/局限

- **62 个终端任务**仍属窄域，且限时 15 分钟至 8 小时，长程任务覆盖不足。
- **默认配置**下测（贴近日常用法），但因此无法回答「调优后谁最好」。
- **后四个冠军置信度低**（25%–47%），榜单易被误读为确定性排序。
- reward hacking 审计拦截了 216 次，但审计本身的漏检率未披露。
- 供应商自建榜单存在利益关联（Runta 卖 runtime，Baseten 卖推理），方法论透明度可圈但独立性需外部复核。
