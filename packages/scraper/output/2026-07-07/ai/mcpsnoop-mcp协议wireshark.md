## 技术定义 (What)

mcpsnoop是一个MCP协议的透明代理和实时终端UI（TUI）。它坐在AI客户端和MCP服务器之间的真实数据路径上，捕获并展示每一个JSON-RPC帧。不同于官方MCP Inspector以独立客户端连接（永远看不到真实客户端的流量），mcpsnoop作为shim包裹服务器命令，转发字节的同时将副本实时推送到TUI，让开发者看到模型真正调用了什么工具、传了什么参数、响应是什么。

## 行业痛点 (Why)

MCP协议正在快速成为AI Agent连接外部工具的标准，但调试MCP集成极其痛苦：
- **工具静默不被调用**：模型决定不调用某个工具，但开发者不知道为什么
- **参数错误难以发现**：模型传了错误参数，但日志中难以追踪
- **调用挂起无反馈**：请求发出后无响应，不知道卡在哪一端
- **官方Inspector看不了真实流量**：它作为独立客户端连接，永远看不到你的Cursor/Claude Code实际发送了什么

## 旧范式 vs 新范式

- **旧做法**：使用MCP Inspector旁路连接（看不到真实流量），或翻阅服务器日志猜测问题，或打断点逐帧调试
- **新做法**：在真实数据路径中插入透明代理，实时看到客户端和服务器之间的每一帧通信，支持过滤、回放、导出

## 生产力影响 (How)

1. **MCP开发调试效率提升10x+**：从翻日志猜测到实时看到完整通信流
2. **协议问题定位从小时级降到分钟级**：慢调用、错误调用、未调用一目了然
3. **会话可导出可回放**：JSON/HTML/Text三种格式导出，支持事后复盘
4. **零配置启动**：`mcpsnoop -- node server.js` 即可，无需额外设置

## 采用成本

- **时间**：5分钟内上手，替换MCP配置中的服务器命令即可
- **金钱**：完全免费，MIT开源
- **学习曲线**：极低——如果你用过Wireshark，概念完全对应；如果没用过，TUI界面直观

## 采用案例

- **MCP服务器开发者**：包裹自己的服务器命令，实时观察所有客户端的调用行为
- **AI应用开发者**：调试Cursor/Claude Code与MCP服务器的集成问题
- **MCP协议研究者**：捕获完整会话，分析模型实际使用的工具调用模式
- **Streamable HTTP模式**：`mcpsnoop http --target http://localhost:3000/mcp` 作为反向代理

## 风险/局限

- **仅支持MCP协议**：不适用于其他Agent-Tool通信协议（如OpenAI Function Calling）
- **安全注意**：代理会看到所有通信内容，不应在不信任的服务器上使用
- **单二进制依赖**：Go编译，无运行时依赖，但需要重新编译才能自定义
